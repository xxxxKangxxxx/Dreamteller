## 1.5 build 9 묶음 — 출시 후 첫 업데이트 🆕

> 신설 2026-08-11 (출시 당일, 실기기 스모크 후). 아래 B로 시작하는 항목은 **앱 코드**라 EAS 빌드 1회 + 심사 사이클이 필요하다 → **모아서 한 번에.**
> S로 시작하는 항목은 **서버 전용**이라 빌드·심사 없이 즉시 배포 가능하므로 **먼저 진행한다.**

### 이미 코드 반영됨 (빌드만 하면 실림)
- **Premium 표기 제거** (커밋 `2bae6da`, 2026-08-08) — 승인 바이너리가 build 8이라 현재 출시본에는 `FREE` 뱃지 / "프리미엄으로 업그레이드" / `프리미엄 알아보기` 막다른 길 버튼 / 카드 워터마크 `FREE`가 **그대로 노출 중**. build 9의 최우선 동기

### C-1 대화 구조 개편 — 턴 카운터 → 슬롯 채우기 ⭐ ✅ **코드 완료(2026-08-16), 배포 대기**

> 서버·앱을 같이 건드리지만 **하위 호환 설계라 서버를 먼저 배포해도 안전**하다. 그래서 build 9를 기다리지 않는다.

**문제** — `step`이 순수한 턴 카운터(`next_step = min(step+1, 5)`)여서 답변 내용과 무관하게 장소→인물→사건→감정을 기계적으로 물었다. 사용자가 첫 답변에 다 말해도 **이미 답한 것을 또 묻는다.** 첫 질문마저 "어디에 있었는지 말해줘"로 장소만 콕 집어 **단답을 유도**하고 있었다.

**변경**
- 진행 판정을 **슬롯 4개**(`place`/`people`/`event`/`emotion`) 충족 여부로 전환. 모델이 매 턴 대화 전체를 다시 읽고 재판정
- **판정을 별도 호출로 분리하지 않음** — 답변과 슬롯 상태를 한 번의 호출에서 JSON으로 함께 받는다. 별도 추출 호출이면 턴당 Gemini 왕복이 2배가 되는데 대화는 이미 꿈 1건 비용의 32%(1-1a)
- 첫 질문을 **개방형**으로 교체 — 한 번에 다 쏟아내는 걸 막지 않고 유도. 최선 경로가 1턴 답변 → 2턴째 완료
- `complete`는 **모델 판단이 아니라 서버가 슬롯으로 재계산** (모델이 그 필드만 틀려 대화가 조기 종료/무한 지속되는 사고 방지)
- **최대 5턴 안전망** — 빈 슬롯은 `"기억나지 않음"`으로 메우고 강제 종료
- 진행 표시 UI를 `N/5단계` → **점 4개 + "N/4 담김"** 으로 교체
- 곁다리: `stream_chat`의 **가짜 스트리밍 3겹 구조(E3)** 가 JSON 출력 전환으로 자연 해소됨 → `chat_turn` 단일 함수로 평탄화

**하위 호환 (중요)** — build 8이 스토어에 라이브라 `text`/`nextStep`/`complete`는 유지. `step`은 받되 무시하고(진실 소스는 `messages`), `nextStep`은 **채워진 슬롯 수 + 1**로 환산해 내려준다. `slots`는 추가 필드라 build 8은 무시 → **서버 선배포 안전**.

## 5. 반복 실수 방지 메모 (운영 노하우)

- **capability 추가 후 첫 EAS 빌드는 대화형 + Apple 로그인(Y)** — `--non-interactive`는 프로파일 재생성 못 해 실패 (build 6 사례). 이후엔 재사용 가능
- **EAS Free 월 iOS 15빌드** — 수정은 모아서 한 빌드에, `eas submit`은 한도 미소비
- **tsc는 반드시 `cd app && npx tsc --noEmit`** — 상위 디렉터리에서 실행하면 엉뚱한 tsc 설치됨
- **ASC URL 입력은 직접 타이핑** — 붙여넣기 시 숨은 문자로 "형식 오류" 발생 사례
- **Supabase resume 후 Auth 토글 재확인** (1-3 참조)
- **게스트 유저는 email이 비어 있어 대시보드에서 User ID로 검색해야 보임**
- **ASC에는 "개발자 답변 대기" 상태값이 없음** — 심사 중 정보 요청(2.1(b) 등)도 `심사를 통과하지 못함` + `해결되지 않은 문제`로 렌더됨. **빨간 X만 보고 재제출을 판단하면 안 됨.** 심사관이 이미 열어보고 질문한 빌드는 담당자가 배정된 상태라, 섣부른 재제출은 큐 리셋 위험(7월 한 달 대기의 재현)
- **Resolution Center 답장만으로 심사가 재개된다** — Apple 공식 문서엔 명시가 없어 8/8에 판단이 갈렸던 지점. 8/11 승인으로 실증됨(답장 확인 6분 뒤 승인). 다음 정보 요청 때는 대기가 정답
- **재제출 ≠ 새 빌드** — `Resubmit to App Review`는 업로드된 기존 빌드를 그대로 재제출하므로 EAS 빌드 한도 미소비
- **거래자 자격과 판매 지역 목록은 별개 컨트롤** — 비거래자로 신고해도 판매 지역에서 EU 국가가 체크 해제되지는 않음(175개국 그대로). 실제 노출은 거래자 자격이 통제하므로 목록을 수동으로 손댈 필요 없음
