## 2. 1차 반려 — 사유 5개와 대응

> 원문 답장: [`REVIEW_REPLY.md`](./REVIEW_REPLY.md)

| # | 가이드라인 | Apple의 지적 | 우리 대응 | 성격 |
|---|---|---|---|---|
| 1 | **4.3(b) Design: Spam** | 운세·점성술 카테고리 포화 | 앱 이름·부제·설명·키워드에서 **운세 뉘앙스 전면 제거** + "운세/점/타로가 아닌 꿈 일기장"으로 재포지셔닝. 해몽은 "융 심리학 기반 자기 성찰 도구"로 명시 | 🔴 **논증 필요** — 코드로 못 푸는 유일한 항목 |

| 3 | **5.1.1(v) 강제 가입** | 로그인 없이 핵심 기능 못 씀 | 게스트 모드(Supabase 익명 로그인) — 기록·해몽·아카이브 전부 로그인 없이 사용 가능 | 🟢 기계적 |
| 4 | **5.1.1(v) 계정 삭제** | 인앱 계정 삭제 부재 | 설정 → 계정 삭제(2단계 확인) + 서버 `DELETE /api/account`. **화면 녹화를 첨부** | 🟢 기계적 |
| 5 | **2.1 Information Needed** | 데모 계정 로그인 불가 | 비밀번호 정정 + "OTP는 가입 1회만, 이후 이메일+비번 즉시 로그인" 명시 + 게스트 대안 안내 | 🟢 기계적 |

**결과**: 재제출 후 이 5개는 **한 번도 재언급되지 않았다.** 전부 해소된 것으로 판단.

### 4.3(b)에서 실제로 통한 논리

가장 어려운 항목이었고, 다음에도 반복될 가능성이 높아 논리 구조를 남긴다.

1. **부인부터 하지 않았다.** "우리는 운세앱이 아니다"만 반복하면 심사관에겐 회피로 읽힌다.
2. **앱의 루프를 한 문장으로 제시**했다 — `write → keep → reflect` (적다 → 간직하다 → 돌아보다). 카테고리 논쟁을 제품 정의 논쟁으로 옮긴 것.
3. **해몽 기능은 인정하되 프레이밍을 바꿨다** — "미래 예측"이 아니라 "융 심리학 기반 자기 성찰". 그리고 **그 문장을 앱 안과 App Store 설명에 실제로 넣었다.** 말만 바꾼 게 아니라 노출면을 바꿨다는 게 핵심.
4. **검증 가능한 변경을 함께 제시** — 이름·부제·설명·키워드에서 운세 단어 0건. 심사관이 즉시 확인 가능한 사실.

## 3. 2차 — Guideline 2.1(b) 정보 요청 (반려 아님)

> 원문 답장 + 상세 분석: [`REVIEW_REPLY_2.md`](./REVIEW_REPLY_2.md)

### 무엇이었나

31일 만에 심사에 진입한 build 8에 대해, **반려가 아니라 "심사 진행 중 질의"** 가 왔다. 메일 본문이 `We have started our review, but we need additional information to continue`이고 `Please reply to this message in App Store Connect`로 **답장을 명시적으로 지시**한다.

내용은 비즈니스 모델 4문항 — 요지는 **"결제 수단이 하나도 없는데 왜 유료 등급이 있는 것처럼 보이는가"**.

### 왜 받았나 (원인 분석)

심사관은 코드도 `docs/`도 볼 수 없다. **노출 표면은 ① 화면 UI ② ASC 입력값 ③ 링크된 웹페이지, 이 셋뿐이다.** 이 기준으로 전수 점검해 찾아낸 것:

| 위치 | 노출 문구 | 위험도 |
|---|---|---|
| `SettingsScreen` | 프로필 옆 `FREE` 뱃지 | 🔴 최상 |
| `InterpretScreen` | "프리미엄으로 업그레이드하면 무제한" + `프리미엄 알아보기` 버튼(→ 구독 UI 없는 막다른 길) | 🔴 최상 |
| `DreamCardScreen` | 공유 카드 워터마크 `DREAMTELLER / FREE` | 🟠 높음 |
| `web/terms.html` 제11조 | "요금·결제·환불" 조항 | 🟠 높음 |
| `web/privacy.html` | 수집 항목 "요금제 상태" | 🟡 중간 |

**가장 유력한 트리거**: 지난 반려의 5.1.1(v) 인앱 계정 삭제를 **재검증하려면 심사관이 반드시 설정 화면에 들어가야 했고**, 거기서 `FREE` 뱃지를 봤다. → "FREE가 있으면 유료도 있다 → 구매 버튼이 없다 → 외부 결제인가?"

> 💡 **일반화**: 지난 반려 항목을 고치면 심사관은 **반드시 그 화면에 들어온다.** 그 경로에 있는 다른 요소가 새 질문을 만든다. 수정한 화면 주변을 함께 점검할 것.

### 어떻게 답했나

1. **부인이 아니라 인정 후 설명.** 4번 질문(IAP 없이 해제되는 유료 기능)에 "그런 거 없다"가 아니라 **"FREE 뱃지와 Premium 문구가 존재한다는 걸 먼저 인정하고, 왜 무해한지 설명"** 하는 구조로 썼다. 심사관이 이미 그 화면을 봤으므로 부인 톤은 회피로 읽힌다.
2. **무료 한도(월 30건/5회)는 페이월이 아니라 Gemini 종량 과금 통제**임을 명시.
3. **약관 제11조를 실제로 개정해서 배포**했다 — 전면 무료·결제 수단 부재 + **"향후 유료 도입 시 인앱결제로만 제공, 외부 결제 경로 미사용"** 원칙을 조항으로 신설. 부칙에 "이용자에게 불리한 변경 아님"을 명기해 약관 개정 사전고지 의무 이슈도 회피.
4. **진행 방식을 직접 물었다** — ⓐ "현 build 8은 준수 상태라 판단하나, 그럼에도 새 빌드가 필요하면 알려달라" ⓑ "ASC가 Unresolved Issues인데 심사 재개에 우리 쪽 조치가 필요하면 알려달라". **순서가 중요**: 준수 주장 → 협조 제안. 역순이면 불필요한 재빌드를 자초한다.

### 결과

**새 빌드도 재제출도 없이 승인.** 답장 확인 6분 뒤 승인 메일. 준비해둔 build 9(Premium 표기 제거)는 결국 쓰지 않았고 다음 업데이트로 넘어갔다.

## 6. 영문 답장 톤 — 반복 적용할 원칙

네 통을 쓰면서 굳어진 원칙. 전부 통했다.

1. **감사 → 항목별 대응 → 추가 정보 제안 → 감사**로 감싼다.
2. **가이드라인 번호를 소제목으로** 달아 1:1 대응시킨다. 심사관이 체크하기 쉽게.
3. **부인보다 인정 후 설명.** 심사관이 이미 본 것을 없다고 하면 회피로 읽힌다.
4. **검증 가능한 사실을 넣는다.** "제거했습니다"보다 "이름·설명·키워드에서 제거했으며 현재 0건"이 강하다.
5. **준수 주장을 먼저, 협조 제안을 나중에.** 역순이면 불필요한 작업을 자초한다.
6. **서명은 개인 실명 + 역할** (`Yeongmo Kang / Developer, DreamTeller`).
7. 요청하지 않은 정보는 넣지 않는다. 질문 수만큼만 답한다.

## 7. 함정 모음 — 다음에 또 걸릴 것들

### ASC 상태 표기

- **ASC에는 "개발자 답변 대기" 상태값이 없다.** 심사 중 정보 요청도 `심사를 통과하지 못함` + `해결되지 않은 문제`(빨간 X)로 렌더된다. **빨간 X만 보고 반려로 판단하면 안 된다.** 메일 본문을 읽고 반려인지 질의인지 구분할 것.
- **Resolution Center 답장만으로 심사가 재개된다.** Apple 공식 문서(`Manage a submission with unresolved issues`)에는 이 설명이 없고 `Resubmit to App Review`만 기술돼 있어 8/8에 판단이 갈렸다. **8/11 승인으로 실증됨** — 답장 후 대기가 정답.
- **재제출 ≠ 새 빌드.** `Resubmit to App Review`는 업로드된 기존 빌드를 그대로 재제출하므로 **EAS 빌드 한도를 쓰지 않는다.**
- 심사관이 이미 열어보고 질문한 빌드는 **담당자가 배정된 상태**다. 섣부른 재제출은 그 컨텍스트를 버리고 큐로 되돌아가는 것.

### 제출 차단 요소

- **`supportsTablet: true`면 13인치 iPad 스크린샷이 필수**다. 바이너리 속성이라 재빌드 없이는 못 끈다 → 스크린샷 제작이 유일 해법. (`app-store/screenshots/ipad.html` + `build-ipad.sh`로 2048×2732 합성)
- **ASC URL 입력은 직접 타이핑.** 붙여넣기 시 숨은 문자로 "형식 오류"가 난 사례 있음.
- **수동 릴리스면 승인돼도 자동으로 안 올라간다.** `배포 → 이 버전 출시` 직접 클릭. 스토어 노출까지 최대 24시간(실제로는 약 5분).

### 규정 준수 (계약 탭)

- **EU DSA 거래자 자격** — 미신고면 EU 스토어프론트 미노출. 신고하면 **주소·전화번호가 EU 제품 페이지에 공개**된다. 개인 개발자는 트레이드오프를 따져야 한다. `거래자 아님/EU 배포 계획 없음`을 고르면 배너가 해소된다.
- **거래자 자격과 판매 지역 목록은 별개 컨트롤이다.** 비거래자로 신고해도 판매 지역에서 EU 국가가 체크 해제되지는 않는다(175개국 그대로). 실제 노출은 거래자 자격이 통제하므로 목록을 수동으로 손댈 필요 없다.
- **한국 비즈니스 연락처** — 입력한 이메일이 **한국 App Store 제품 페이지에 공개 표시**된다. 사업자등록번호(BRN) 없으면 `아니요`로 진행 가능.
- **무료 앱 계약이 활성이어야 배포된다.** 만료일 관리 필요 (현재 2027-05-10).

## 8. 다음 앱 사전 예방 체크리스트

이번에 겪은 것들을 **제출 전에** 막기 위한 목록.

### 제출 전 — 노출 표면 전수 점검

심사관이 보는 건 ① 화면 UI ② ASC 입력값 ③ 링크된 웹페이지뿐. 이 셋만 훑는다.

- [ ] **구현하지 않은 기능의 흔적이 UI에 남아 있지 않은가** — 이번 2.1(b)의 정확한 원인. 플랜 뱃지, "업그레이드", 비활성 버튼, 워터마크
- [ ] **막다른 길 버튼이 없는가** — 눌렀는데 아무것도 없는 버튼은 질문을 부른다
- [ ] 약관·개인정보처리방침이 **앱의 실제 상태와 일치하는가** (결제 없는데 요금 조항이 있다든지)
- [ ] 앱 이름·부제·설명·키워드에 **카테고리 오해를 살 단어가 없는가**
- [ ] 데모 계정이 **실제로 로그인되는지 직접 확인** (OTP·2FA가 있으면 심사관은 못 뚫는다 → 우회 경로를 메모에 명시)
- [ ] 계정 삭제·게스트 모드 등 5.1.1 요건 충족
- [ ] Sign in with Apple (타 소셜 로그인이 있다면 필수)
- [ ] iPad 스크린샷 (`supportsTablet: true`인 경우)

### 제출 시

- [ ] App Review Information에 **데모 계정 + 우회 경로 + 필요 시 화면 녹화 첨부**
- [ ] 심사 메모(영문)에 앱의 정체성을 한 문장으로 — 카테고리 오해 선제 차단
- [ ] 수동/자동 릴리스 선택 확인

### 반려당했을 때

1. **메일 본문을 읽고 반려인지 질의인지 먼저 구분** (ASC 표기는 둘 다 빨간 X)
2. 사유를 **코드로 풀 것 / 논증으로 풀 것**으로 분류 — 논증 항목이 시간을 잡아먹는다
3. 코드 항목부터 처리하고, 논증 항목은 **노출면(앱 내 문구·스토어 설명)까지 실제로 바꿔서** 검증 가능하게 만든다
4. 답장은 §6 원칙대로, 가이드라인 번호 1:1 대응
5. **빌드 한도를 확인하고 수정을 모아서 한 빌드에** (EAS Free는 월 iOS 15빌드, `eas submit`은 한도 미소비)
